# IG Guard 6.0.3 — fixes from a second audit

Documented: **26 November 2026 (Hong Kong)**. Bundled Terms revision: `2026-11-26-v9`, unchanged from 6.0.2, so no "Terms updated" notice appears. Earlier version: [6.0.2](6.0.2.md).

Tag and version name `6.0.3`. Version code: 100 plus the GitHub Actions run number of the release run; the installed app shows it. It installs over 6.0 or 6.0.2 and keeps the pairing and data, because it is signed with the same key.

6.0.3 is 6.0.2 with the fixes below. All of them were present in 6.0 or earlier; none comes from the 6.0.2 changes. Everything in the [6.0.2](6.0.2.md) and [6.0](6.0.md) release notes, including the open risks, still applies unless this page says otherwise. ## What changed

**Parent phone**

- **The records-not-delivered warning no longer comes early.** A run of bad heartbeats now ends at any heartbeat that is not bad. Before, only a fully clear one ended it, so a single bad heartbeat hours later could raise the warning at once.
- **A refused multi-part record no longer keeps its parts.** A large record that is complete but then refused has its parts deleted at once. Before, they stayed for up to 3 days and, after about 100 of them, new large records were refused.
- **The child's own account name is no longer set back to an older one.** The parent takes the name only from a newly stored record that is newer than the record the stored name came from. This also covers the name message of families still paired the 5.2 way, using the time the child phone wrote into it.
- **"加入子女 · Add a child" no longer crashes when the parent's signing key cannot be loaded** (for example when the app was killed while the key was first created). It shows "This phone's signing key is unavailable". The app still never makes a new key by itself in that state; the way out is to leave the parent role and set up again.

**Both phones**

- **The list of relay delivery numbers is removed.** It was meant to stop a relay message being handled twice, but the relay gives every delivery a new number, so the list never matched a repeat. Each kind of record has its own repeat check, and those are unchanged. The stored list is deleted on upgrade.
- **Retiring a pairing room no longer holds up sending and receiving.** It runs on its own thread.
- **The password check no longer freezes the screen** on the unlock page and the role-change sheet. The button reads "核對中… · Checking…" while it runs. The lockout is still checked first, every attempt still counts, and a second press during a check is refused.

**Child phone**

- **A second import while scoring is running is scored soon after**, where it waited for the next overnight charge. The job is retried by Android, still only while charging.
- **Large imports are faster.** The 14-day cleanup now uses a database index.

**Code and build**

- About 250 lines of unused code (an old score-file reader and an older scoring routine) and their tests are removed.
- Any hotfix release tag (for example `6.0.3-hotfix.1`) now deploys the relay. Before, only `4.8-hotfix.N` tags did. The GitHub environment `relay-prod` must allow `*-hotfix.*` tags as well; [ci-secrets-hardening.md](../ci-secrets-hardening.md) now also states how that environment is actually set.

## Documents

- No sentence of the Terms, the privacy policy or the deletion guide is made wrong by these changes; the Terms revision is unchanged.
- [local-risk-scoring.md](../local-risk-scoring.md) said several windows of 30 messages were scored per conversation. Only the newest 30 are scored, and that was already so in 6.0; the page is corrected.

## Not fixed, and known limits

- **A phone cannot go back to 6.0.2 or 6.0 after this update without clearing the app's data**, because the database format number changed from 9 to 10. Android does not allow installing an older version over a newer one in any case.
- Two child records with exactly the same time: the account name from the first one stays.
- Families still paired the 5.2 way: the time in their name message is not signed. Pairing again by QR code under "加入子女 · Add a child" is the cure, as before.
- On the role-change sheet, after a correct password the button stays greyed while the parent phone is being notified.
- The limits listed in the [6.0.2 release notes](6.0.2.md) that are not named above still apply.

## Tested, and not tested

Tested:

- 993 unit tests on the Windows development PC; 1 failed there, the known `RelayOutboxTest > concurrentFirstOpenCannotRaceDatabaseCreation`, which fails only on that PC. On GitHub, run 172 passed every test on the code before the last small change; run 170 before it failed with one test that was not named and did not fail again.
- Each fix has a test that fails without it, and each fix was removed again to confirm its test then fails. The removal of the delivery-number list was checked the other way: the new test fails while the list is there, and the whole suite passes without it.
- An upgrade from database format 8 and from 9 (unit tests): format 9 keeps every row and gains the index.

Not tested:

- 6.0.3 on real phones, including the upgrade over 6.0 and 6.0.2.
- Everything listed as not tested in the [6.0.2](6.0.2.md) and [6.0](6.0.md) release notes.
