# Convoy 6.0.4 — fixes from an external bug review

Documented: **28 November 2026 (Hong Kong)**. Bundled Terms revision: `2026-11-26-v10`, unchanged from 6.0.3, so no "Terms updated" notice appears. Earlier version: [6.0.3](6.0.3.md).

Tag and version name `6.0.4`. It installs over 6.0.3 and keeps the pairing and data. Like 6.0.3, it cannot be installed over a phone back to 6.0.2 or 6.0 without clearing the app's data (database format 11).

6.0.4 is 6.0.3 with fixes for bugs found by an external review and a follow-up audit. Each fix has a test that failed before it.

## What changed

**Child phone**
- Agreeing to scores-only mode now discards queued message text on a QR-paired child, so none reaches the parent after the child agreed to text-free mode.
- Changing capture options discards only queued message text; tamper alerts, heartbeats and score reports are kept.
- A very confident score is capped at 100, so the parent no longer refuses every score report.
- The delivery-health numbers use plain digits on every phone language (for example Arabic, Persian, Bengali), so the "records not delivered" notice works there.
- After the phone clock steps back, newly captured messages are no longer refused by the parent.
- A keyword bubble on screen alerts once, and no longer hides the newest message from the stranger check.
- Messages Instagram shows again are skipped before signing, so a new message no longer costs many key operations.
- A wrong-password lockout counts down only while the phone runs: an ended lockout no longer comes back after a reboot, and moving the clock forward still cannot shorten one.
- After the phone clock is set back, heartbeats keep going, so the parent no longer gets a false "offline" warning.

**Pairing**
- The child pairing sheet stays live after "Scan again", after two bad QR codes in a row, and after the camera is allowed in Settings.
- The camera preview is drawn upright and not squashed, in portrait and landscape (checked on a tablet).
- A child clock too far behind now refuses the QR code up front and asks to check the date and time.
- A relay refusal caused by a wrong phone clock retries with the relay's time instead of ending the pairing.
- A Keystore failure while cancelling a pairing no longer crashes the app.

**Parent phone**
- "Delete old relay room" deletes the room only after the relay confirmed the child's release.
- The weekly statistics remember only counted alerts, so they no longer grow with every record.
- The trusted friends list accepts a full-width comma (，).

**Relay and connection**
- The reconnect back-off starts again once the relay is ready.
- An alert that could not be queued is no longer blocked as a duplicate; in scores-only mode two different messages are two alerts again.
- The live check after a relay deploy also tests a v2 child connection and deletes its test room.

## 6.0.4-hotfix.1

- A record whose first send hit a closing relay connection is now resent when its retry is due, instead of waiting for some later event. Before, a QR pairing could stall until the next heartbeat.

## Not changed or not tested

- Not tested on the LG phone; the pairing, AI scoring and camera fixes were checked on a Redmi Pad SE tablet with debug builds.
- Known limits: with 8 or more queued parent commands the relay can hold back a pairing record (needs a relay protocol change); lockout time in the last few minutes before a reboot is not counted (the child waits longer, never shorter).
