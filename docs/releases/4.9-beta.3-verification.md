# 4.9-beta.3 verification

Checked on 16 November 2026 (Hong Kong).

- First-launch regression tests cover three initially unticked acknowledgments, acceptance gating, exact displayed Terms and document hash, encrypted receipt, original-revision preservation, normal relaunch, decline/Back to Home, corrupt records, failed persistence and successful retry, existing child-service grants, existing queued records, direct capture/relay entry points and deferred pairing confirmation.
- A simulated Android disk-commit failure verifies that a failed save cannot leave the in-memory receipt enabling collection. Receipt readers and writers share a lock; rollback happens before gates can reopen.
- An upgrade regression verifies that child components remain enabled and pending consent does not call Accessibility `disableSelf()`. Event processing remains gated until acceptance. The notification listener unbinds while consent is pending, retains notification-access authorization and schedules its heartbeat after the post-acceptance rebind. Android retains control of its permission grants.
- Native 390 × 844 Android renders check the introductory disclosures and final choice controls. Checkbox/link/button contrast is set explicitly for the light consent surface. The full bilingual Terms are selectable native text and work offline.
- The release verification gate requires the existing trusted certificate, package/version, non-debuggable build, and byte-for-byte equality between packaged Terms and `docs/ig-guard-terms-of-service.md`. A mismatched-Terms fixture is rejected.

Local verification: **262 Android tests**, **33 Python build/release checks**, Android lint with no errors, debug and unsigned release assembly. CI separately builds and verifies a signed APK using the protected signing configuration. Source/build verification is not evidence that an already-installed phone has updated.

Canonical Terms revision: `2026-11-16-v1`; UTF-8 SHA-256: `744d51bd3116032aeef243fa685ad5965fc1a736410c2db2b2ad74e715b1c058`.

Limits: tests run under Robolectric, including a test-only Android Keystore provider and synthetic notification/accessibility state. The provider is excluded from production builds. These checks do not certify physical-device Keystore behaviour, permission persistence on every vendor's Android build, actual Instagram capture or user comprehension. Device owners should verify the consent flow, paired-parent identity, permissions and capture scope on both real phones before use. The Terms describe section 52's limited wording; this release is not a legal certification or Meta approval.
